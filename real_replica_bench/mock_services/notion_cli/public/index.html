CLI Reference

Complete reference for every command, flag, and option available in the Notion CLI (ntn).

Global Flags

These flags can be used with any command.

FlagDescriptionDefault
-v, --verboseEnable verbose output for debuggingfalse
--workers-config-filePath to the workers configuration file./notion-workers.toml
-V, --versionPrint the CLI version-
-h, --helpPrint help information for a command-

Environment Variables

Environment variables that configure CLI behaviour. These take precedence over config files.

VariableDescription
NOTION_API_TOKENAPI token used for authentication instead of the token stored in the keyring.
NOTION_KEYRINGOverride the default keyring backend (system, file, memory).
NOTION_WORKERS_CONFIG_FILEPath to the workers configuration file, equivalent to --workers-config-file.
NOTION_WORKSPACE_IDDefault workspace ID to use when not specified in the command.

ntn login

Authenticate the CLI with your Notion account. Opens a browser window for the OAuth flow and stores the resulting token in your system keyring.

ntn login [flags]

Options

FlagDescription
--token <token>Authenticate using an API token directly instead of browser OAuth
--workspace <id>Set the default workspace after login

Example

# Interactive browser login
ntn login

# Token-based login
ntn login --token ntn_v2_abc123...

ntn logout

Remove stored authentication credentials from the system keyring.

ntn logout [flags]

Options

FlagDescription
--allRemove credentials for all workspaces

Example

ntn logout
ntn logout --all

ntn workers new

Scaffold a new worker project. Creates a directory with the config file, source template, and package manifest.

ntn workers new <name> [flags]

Options

FlagDescription
--template <name>Starter template (basic, sync, webhook)
--dir <path>Parent directory (default: current directory)

Example

ntn workers new my-sync-worker --template sync

ntn workers deploy

Build and deploy the current worker project to Notion's infrastructure. Reads the worker configuration from notion-workers.toml.

Alias: ntn deploy 
ntn workers deploy [flags]

Options

FlagDescription
--dry-runValidate and build without deploying
--env <name>Deploy to a specific environment (production, staging)
--message <msg>Deployment message

Example

ntn workers deploy
ntn workers deploy --env staging --message "Fix sync timeout"
ntn deploy --dry-run

ntn workers create

Create a new worker registration in the workspace without deploying code. Useful for CI/CD pipelines that deploy separately.

ntn workers create <name> [flags]

Options

FlagDescription
--description <text>Human-readable description
--jsonOutput in JSON format

Example

ntn workers create my-worker --description "Syncs CRM contacts"

ntn workers delete

Delete a worker and all its associated resources (runs, logs, environment variables). This action is irreversible.

ntn workers delete <worker-id> [flags]

Options

FlagDescription
--forceSkip confirmation prompt

Example

ntn workers delete wrk_abc123
ntn workers delete wrk_abc123 --force

ntn workers exec

Execute a worker locally for testing. The worker runs against the live Notion API but does not count as a production run.

ntn workers exec [flags]

Options

FlagDescription
--input <json>JSON payload passed to the worker's handler
--timeout <seconds>Maximum execution time (default: 30)
--env-file <path>Load environment variables from a file

Example

ntn workers exec
ntn workers exec --input '{"database_id":"db_abc"}' --timeout 60

Options

FlagDescription

ntn workers sync pause

Pause scheduled synchronisation for the worker. The worker remains deployed but no automatic syncs will run.

ntn workers sync pause [worker-id]

Example

ntn workers sync pause
ntn workers sync pause wrk_abc123

ntn workers sync resume

Resume scheduled synchronisation for a paused worker.

ntn workers sync resume [worker-id]

Example

ntn workers sync resume
ntn workers sync resume wrk_abc123

ntn workers sync state get

Retrieve the persisted sync cursor/state for the worker. The state is a JSON blob used to track incremental sync progress.

ntn workers sync state get [worker-id] [flags]

Options

FlagDescription
--jsonOutput in JSON format

Example

ntn workers sync state get wrk_abc123 --json

ntn workers sync state reset

Reset the persisted sync state. The next sync will start from scratch as a full sync.

ntn workers sync state reset [worker-id] [flags]

Options

FlagDescription
--forceSkip confirmation prompt

Example

ntn workers sync state reset wrk_abc123

ntn workers env set

Set an environment variable for the worker. The value is encrypted at rest and injected at runtime.

ntn workers env set <key> <value> [flags]

Options

FlagDescription
--worker <id>Target worker (defaults to current project)
--secretMark as a secret (hidden in logs and UI)

Example

ntn workers env set API_KEY sk-abc123 --secret
ntn workers env set DATABASE_URL postgres://localhost/mydb

ntn workers env list

List all environment variables configured for the worker. Secret values are redacted.

Alias: ntn workers env ls 
ntn workers env list [flags]

Options

FlagDescription
--worker <id>Target worker
--jsonOutput in JSON format

Example

ntn workers env list
ntn workers env ls --json

ntn workers env unset

Remove an environment variable from the worker.

ntn workers env unset <key> [flags]

Options

FlagDescription
--worker <id>Target worker

Example

ntn workers env unset API_KEY

ntn workers env pull

Download the worker's environment variables to a local .env file. Secret values are included in plaintext.

ntn workers env pull [flags]

Options

FlagDescription
--worker <id>Target worker
--file <path>Output file path (default: .env)

Example

ntn workers env pull
ntn workers env pull --file .env.local

ntn workers env push

Upload environment variables from a local .env file to the worker. Existing variables with matching keys are overwritten.

ntn workers env push [flags]

Options

FlagDescription
--worker <id>Target worker
--file <path>Input file path (default: .env)
--replaceReplace all variables instead of merging

Example

ntn workers env push
ntn workers env push --file .env.production --replace

ntn workers oauth start

Start the OAuth flow for a third-party integration configured in the worker. Opens a browser for the user to authorize access.

ntn workers oauth start <provider> [flags]

Options

FlagDescription
--worker <id>Target worker
--scopes <list>Comma-separated list of OAuth scopes
--port <n>Local callback server port (default: 8400)

Example

ntn workers oauth start github --scopes repo,read:user
ntn workers oauth start salesforce --worker wrk_abc123

ntn workers oauth token

Retrieve the current OAuth access token for a provider. Automatically refreshes expired tokens.

ntn workers oauth token <provider> [flags]

Options

FlagDescription
--worker <id>Target worker
--jsonOutput full token payload in JSON

Example

ntn workers oauth token github
ntn workers oauth token salesforce --json

ntn workers oauth show-redirect-url

Print the OAuth redirect URL that must be registered with the third-party provider for the worker.

ntn workers oauth show-redirect-url [flags]

Options

FlagDescription
--worker <id>Target worker

Example

ntn workers oauth show-redirect-url
# Output: https://workers.notion.com/oauth/callback/wrk_abc123

ntn api <path>

Make an authenticated request to the Notion API. Supports all HTTP methods and automatically handles pagination for list endpoints.

ntn api <path> [flags]

Options

FlagDescription
-X, --method <verb>HTTP method (GET, POST, PATCH, DELETE)
-d, --data <json>Request body (JSON string or @file)
--paginateAutomatically follow pagination cursors
-q, --jq <expr>JQ expression to filter the response
--rawOutput raw response without formatting

Example

# Get current user
ntn api /v1/users/me

# Query a database
ntn api /v1/databases/db_abc/query -X POST -d '{"page_size":10}'

# List all pages with jq filter
ntn api /v1/search -X POST --paginate -q '.results[].id'

ntn api ls

List available Notion API endpoints with their methods and descriptions. Useful for discovering API paths without leaving the terminal.

ntn api ls [flags]

Options

FlagDescription
--filter <text>Filter endpoints by path or description

Example

ntn api ls
ntn api ls --filter database

ntn datasources query

Query a connected datasource using its native query language or a Notion filter object. Returns results as JSON.

ntn datasources query <datasource-id> [flags]

Options

FlagDescription
--query <string>Query string in the datasource's native format
--filter <json>Notion-style filter object (JSON)
--limit <n>Maximum records to return
--jsonOutput in JSON format

Example

ntn datasources query ds_abc --query "SELECT * FROM contacts LIMIT 10"
ntn datasources query ds_abc --filter '{"property":"status","equals":"active"}' --json

ntn datasources resolve

Resolve a datasource reference to its underlying connection details (type, host, database name). Useful for debugging connectivity issues.

ntn datasources resolve <datasource-id> [flags]

Options

FlagDescription
--jsonOutput in JSON format

Example

ntn datasources resolve ds_abc
ntn datasources resolve ds_abc --json

ntn pages trash

Move a page to the trash. The page can be restored from the trash within 30 days.

ntn pages trash <page-id> [flags]

Options

FlagDescription
--forceSkip confirmation prompt

Example

ntn pages trash pg_abc123
ntn pages trash pg_abc123 --force

ntn pages get

Retrieve a page's properties and metadata. Optionally include page content (blocks).

ntn pages get <page-id> [flags]

Options

FlagDescription
--include-contentAlso fetch the page's block content
--jsonOutput in JSON format

Example

ntn pages get pg_abc123
ntn pages get pg_abc123 --include-content --json

ntn pages create

Create a new page in a database or as a child of another page.

ntn pages create [flags]

Options

FlagDescription
--parent <id>Parent page or database ID (required)
--title <text>Page title
--properties <json>Page properties as JSON
--content <json>Block content as JSON array
--jsonOutput in JSON format

Example

ntn pages create --parent db_abc --title "Meeting Notes"
ntn pages create --parent pg_abc --title "Sub Page" --content '[{"type":"paragraph","paragraph":{"text":[{"type":"text","text":{"content":"Hello"}}]}}]'

ntn pages update

Update a page's properties. Only specified properties are modified; others remain unchanged.

ntn pages update <page-id> [flags]

Options

FlagDescription
--title <text>Update the page title
--properties <json>Properties to update as JSON
--icon <emoji|url>Set the page icon
--cover <url>Set the page cover image URL
--jsonOutput in JSON format

Example

ntn pages update pg_abc123 --title "Updated Title"
ntn pages update pg_abc123 --properties '{"Status":{"select":{"name":"Done"}}}'

ntn files create

Upload a file to the Notion workspace. Returns the file object with a download URL.

ntn files create <file-path> [flags]

Options

FlagDescription
--name <name>Override the file name
--content-type <mime>Override the MIME type
--jsonOutput in JSON format

Example

ntn files create ./report.pdf
ntn files create ./logo.png --name "company-logo.png" --json

ntn files get

Retrieve metadata for a file, including its download URL, size, and MIME type.

ntn files get <file-id> [flags]

Options

FlagDescription
--downloadDownload the file to the current directory
--output <path>Download to a specific path
--jsonOutput in JSON format

Example

ntn files get file_abc123 --json
ntn files get file_abc123 --download --output ./downloads/

ntn files list

List files in the workspace, optionally filtered by page or database.

Alias: ntn files ls 
ntn files list [flags]

Options

FlagDescription
--parent <id>Filter by parent page or database
--limit <n>Maximum number of results
--jsonOutput in JSON format

Example

ntn files list
ntn files ls --parent pg_abc123 --limit 50 --json

FlagDescription

Example

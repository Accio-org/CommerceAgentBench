On the Marketplace Operations team at NorthBridge Accessories, we track product feed quality issues in a DingTalk Docs knowledge base — the `Merchant Feed QA` folder has sub-folders by market, each containing QA documents for individual SKUs. My manager has asked me to produce the weekly feed QA summary for the current review cycle.

The `dws` CLI is available for all document operations — authenticate first with the credentials in `workspace/credentials.txt`. Run `dws --help` to see available commands. No network access.

Which QA documents to include in the summary, how to structure the summary document, and what comment to add on included documents are all defined in `workspace/summary_procedure.md` — **read it before starting**.

Walk through the knowledge base, read the QA documents, decide which ones meet the inclusion criteria, create the summary document, and add the comment on each included document. The knowledge base state IS the deliverable.

我们要上线一款 NovaCast P5 Pro 便携投影仪。发品系统在 http://127.0.0.1:3000，但这次**只开了 HTTP API、没有页面**，请按 `workspace/api_reference.md` 里给的 `/api/cli/*` 端点（带 `Authorization: Bearer local-mock-token`）调用完成发品，闭集字段服务端会做枚举校验，非法值直接 400；填完 `POST /api/cli/submit` 让 session 翻到 `submitted` 就算交付。

资料我都堆在 workspace/ 里了，有点乱：运营总监的发品策略邮件、采购经理在微信群里的消息、几版报价单、几个产品的规格书，还有一整个素材库的照片。先看 workspace/task_brief.md 了解这次要发什么，里面也指了各份资料的位置。报价以最新一版为准，但留意采购经理后来有没有临时改价；定价公式、阶梯结构、分国家的差异定价、计量单位、最小起订量、可售数量、发货期、商品分组、描述与协议要求都按运营总监邮件来。图片在 assets/ 里，是一组没分类的混合拍摄，文件名只有相机自动编号，自己一张张看，把属于这款 NovaCast P5 Pro 的、清晰能用的产品图挑出来传上去，拍得不行的或不是本机的别传。

商品标题、关键词、商品描述都用英文写；属性里的分辨率、亮度、连接方式结合 `product_info/projector_p5_pro_spec.md` 自己填。多个连接方式之间用 ` + `（前后各一个空格）分隔。

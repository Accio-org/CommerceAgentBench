# 双数据源字段裁决规则

## 背景

我们有两个海关数据源记录了相同供应商的出口数据：
- **装货港数据（东营）**：`loading_port_dongying.csv` — 在 FOB（离岸价）基础上记录
- **卸货港数据（广州）**：`discharge_port_guangzhou.csv` — 在 CIF（到岸价）基础上记录

同一供应商在两个数据源中可能出现不一致。以下规则规定每个字段应以哪个数据源为准。

## 字段裁决规则

### 1. weight_kg（重量）
**采用：装货港（东营）数据**
- 理由：货物在装船前称重，装货港数据是原始测量值
- 卸货港重量可能包含包装填充、托盘、或因运输中受潮等因素偏高

### 2. amount_usd（金额）
**采用：卸货港（广州）数据**
- 理由：CIF 价格包含运费和保险费，是合同约定的最终结算价
- 装货港 FOB 价格不含运费保险，不是最终交易金额

### 3. quantity（数量）
**采用：装货港（东营）数据**
- 理由：货物在产地清点装箱，装货港数量是原始清点值

### 4. hs_code（HS 编码 / 海关分类）
**采用：更严格的分类（关税税率更高的那个）**
- 同一商品在装货港和卸货港可能被归入不同的 HS 编码
- 查阅 `tariff_schedule.md` 中的关税税率表
- 对比两个 HS 编码的税率，选择**税率更高**的那个
- 如果税率相同，优先使用装货港编码
- 注意：不是比较 HS 编码数字的大小，而是比较对应的关税税率

### 5. destination_country / buyer / buyer_address（目的地/买方信息）
**采用：卸货港（广州）数据**
- 理由：最终目的地以到港申报为准，买方信息以进口方申报为准

### 6. supplier / supplier_address / manufacturer（供应商信息）
**采用：装货港（东营）数据**
- 理由：供应商和制造商信息以产地海关登记为准

## 非重叠供应商处理

如果某供应商只出现在一个数据源中（只在装货港或只在卸货港数据里），则直接使用该数据源的全部信息，无需裁决。

## 重要注意事项

- **不要取平均值**：对于有冲突的字段，选择规定的数据源，不要对两个值求平均
- **不要对所有字段使用同一个数据源**：不同字段有不同的裁决规则
- **HS 编码裁决需要查表**：必须参考关税税率表，不能凭编码大小判断
- **按供应商汇总后再对比**：对比与裁决均针对每家供应商在各数据源的全部行汇总值（求和）进行

## 对账跟踪规范（Jira / Todoist 业务政策）

以下规范适用于将裁决结果录入跟踪系统时。

### Jira 优先级设置

金额差异按以下公式计算（取整到个位百分比）：

```
金额差异率 = round(|卸货港金额 - 装货港金额| / 装货港金额 × 100)
```

优先级规则：
- 金额差异率 **≥ 10%** → 优先级设为 **Medium**
- 金额差异率 **< 10%** → 优先级设为 **Low**

### Jira 标签规范

每个对账 issue 必须携带以下标签：
- `reconciliation`：所有对账类 issue 均须添加
- `hs-conflict`：装货港与卸货港的 HS 编码存在冲突的供应商，额外添加此标签

### Jira 项目归属

对账类 issue 统一建在 **RECONCILIATION** 项目下（`--project RECONCILIATION`）。

### Todoist 项目归属

后续待办统一建在 Todoist 项目 **海关裁决后续** 下，按任务要求的三个区块（「HS编码复核」「金额确认」「归档完成」）组织。

### DWS 报告结构

- 所有供应商裁决报告统一放在 DWS 文件夹 **海关数据裁决报告** 下
- 每个供应商单独一篇报告，文档名需包含该供应商名称
- HS 编码有过冲突的供应商，其报告中需有单独一行写明最终采用的编码，统一格式：`Resolved HS: <最终采用的HS编码>`（合规系统按此行批量核对，格式请勿变动）
- 另建一篇 **裁决汇总报告**，汇总整体对账与裁决情况
